BNO085 I2C Integration — STM32H7_OMNIBASE_CAN_BNO085
======================================================
Date: 2026-04-28

SUMMARY
-------
Replaced the BNO055 I2C IMU with the BNO085 (SH2/SHTP protocol) in the
FreeRTOS-based robot firmware. A new dedicated FreeRTOS task (IMU_Task)
owns all SH2 communication. The existing telemetry path, UART/CAN tasks,
and ODrive control logic are unchanged.

ASSUMPTIONS
-----------
1. I2C peripheral:   I2C1, 400 kHz, timing register 0x00B03FDB (matched
   reference project; NoStretch DISABLED for clock-stretch support).
2. BNO085 I2C address: 0x4A (7-bit), 0x94 (8-bit for HAL).
   Corresponds to Adafruit BNO085 with PS0=PS1=GND.
3. INT pin:  PD14, active LOW, input with pull-up.
   Note: main.h previously defined MCP2515_CS_Pin = GPIO_PIN_14 on GPIOD,
   but MCP2515/SPI1 is unused (commented out). PD14 is free for BNO085 INT.
4. RST pin:  PD15, active LOW, output push-pull, idle HIGH.
5. IMU_Task priority: osPriorityAboveNormal (same as ODriveTask).
   sh2_service() spends most of its time idle (INT polling returns 0 when
   no data). osDelay(2) in the task loop yields CPU between polls.
6. Telemetry units: BNO085 SH2 rotation vector produces quaternions;
   q_to_ypr() returns RADIANS. The integration converts to degrees
   (×180/π) before placing in telemetryMsg.imu.* so the UART telemetry
   format stays byte-compatible with the previous BNO055 (which output
   degrees in NDOF mode). If your ROS node expects radians, remove the
   RAD_TO_DEG_D multiplication in ODriveTask.
7. BNO085 reporting interval: 20 ms (50 Hz), matching the reference project.
   Change BNO085_REPORT_INTERVAL_US to adjust.
8. IMU_Task stack: 1024 × 4 = 4 KB. SH2 library uses internal packet
   buffers on stack; 4 KB has been verified sufficient in the reference.
9. I2C bus sharing: I2C1 is exclusively owned by IMU_Task; no mutex
   required. If another peripheral is ever added to I2C1, add an
   osMutex around all HAL_I2C_Master_Receive/Transmit calls in
   sh2_hal_impl.c and wherever the second device is accessed.
10. IMU_ENABLED macro: left at 0. The BNO055 driver files (bno055.c,
    bno055_stm32.h) remain in the project but are never called.
    They can be safely removed or left in place.

STM32CubeIDE BUILD CONFIGURATION STEPS REQUIRED
-------------------------------------------------
The .cproject file was updated automatically to add Core/Inc/sh2 to
all include paths. However, Eclipse may cache project settings.

If you get "No such file or directory" errors for sh2.h / shtp.h etc.:

1. Close and reopen the project in STM32CubeIDE (or restart the IDE).
   OR
2. Right-click project → Properties → C/C++ Build → Settings →
   Tool Settings → MCU GCC Compiler → Include paths → Add:
     ${workspace_loc:/${ProjName}/Core/Inc/sh2}
   Repeat for MCU GCC Assembler → Include paths.

After that, do a full clean + rebuild:
  Project → Clean → Build All


VERIFICATION TESTS
------------------
1. BNO085 I2C communication
   - Flash firmware; open USART3 terminal (115200 baud).
   - Expected output within 1 second of reset:
       "IMU_Task: starting BNO085 init"
       "IMU_Task: BNO085 running at 50 Hz"
   - If sh2_open fails, you will see:
       "IMU_Task: sh2_open failed rc=X — halting"
     → Check PD14/PD15 wiring and I2C1 pull-up resistors (4.7 kΩ to 3.3 V).

2. Quaternion / Euler readings in telemetry
   - UART telemetry line format (USART3, 115200 baud):
       "... IMU_yaw=<deg>,IMU_roll=<deg>,IMU_pitch=<deg> ..."
   - With sensor flat (horizontal), yaw should vary slowly, pitch and
     roll should be near 0.
   - Rotate the sensor; confirm all three angles respond.
   - Gyrate the sensor; confirm the angles do NOT freeze or jump wildly.

3. Telemetry output rate / UART
   - The UART_TX_Task waits on CAN_2_UTX_QueueHandle (ODriveTask pushes
     every 10 ms). Confirm the telemetry line rate is ~100 Hz.
   - IMU fields must update; they should not be stuck at 0.0.

4. No interference with CAN/FDCAN ODrive control
   - With CAN_STUB=0 and ODrives connected, drive the robot normally.
   - Confirm ODrive velocity setpoints are delivered (AXIS_Encoder_Vel
     tracks commanded velocity in telemetry).
   - There should be no increase in "CAN TX timeout" messages with
     IMU_Task running.

5. No UART task starvation
   - Send a stream of type-1 velocity commands from ROS (USART3).
   - Confirm all commands are processed; no dropped lines.
   - UART_RX_Task and BT_RX_Task are High priority — they preempt
     IMU_Task (AboveNormal) correctly.

6. No I2C bus lockup
   - Run for >10 minutes. The UART telemetry line should keep printing
     with fresh IMU values.
   - If the bus locks up (HAL_I2C_Master_Receive returns HAL_BUSY),
     the BNO085 INT pin will stay LOW and the firmware will be stuck in
     consecutive I2C reads. This is detectable by IMU_yaw being frozen.
     Resolution: increase BNO085_I2C_TIMEOUT_MS or add I2C bus reset
     logic in sh2_hal_impl.c hal_read().

7. Sensor reset recovery
   - Power-cycle the BNO085 while the MCU is running (if hardware allows).
   - Expected output:
       "IMU_Task: BNO085 reset detected — re-configuring"
   - IMU data should resume within ~500 ms.


BNO085 PINOUT (I2C MODE — current wiring)
------------------------------------------
STM32H7 pin   BNO085 pin   Notes
------------  -----------  --------------------------------------------------
PB6           SCL          I2C1 clock  (AF4, configured by HAL_I2C_MspInit)
PB7           SDA          I2C1 data   (AF4, configured by HAL_I2C_MspInit)
PD15          RST          Active LOW; driven by sh2_hal_impl.c rst_assert/deassert
PD14          INT          Active LOW input with pull-up; polled by hal_read()
3.3 V         VIN / 3V3    Board power
GND           GND          Common ground
GND           PS0          } Both LOW → selects I2C mode, address 0x4A (7-bit)
GND           PS1          }

External pull-up resistors required: 4.7 kΩ from PB6 to 3.3 V
                                      4.7 kΩ from PB7 to 3.3 V
(The Adafruit BNO085 breakout includes on-board 10 kΩ pull-ups, which
 are sufficient but slower; 4.7 kΩ is preferred for 400 kHz I2C.)

Unused SPI pins still configured as GPIO (harmless):
  PB4 → former CS   (output, idle HIGH — not connected to BNO085)
  PA4 → former WAKE (output, idle HIGH — not connected to BNO085)
These can be repurposed or left floating.


KNOWN LIMITATIONS / FUTURE WORK
---------------------------------
- ControlTask (ControlTaskHandle) is declared but not started. If you
  add a yaw-based heading controller there, read g_bno085_yaw directly
  (it is a volatile global, accessible from any file in main.c).
- BNO055 driver files are still compiled (bno055.c). They add ~2 KB to
  flash. Remove them from the build if flash space is tight.
- The SH2 library prints to stdout via printf() in some error paths
  (sh2.c). These use USART3 through the retarget. If silent operation
  is needed, define SH2_NO_PRINTF or redirect stdout.
- Only SH2_ROTATION_VECTOR (9-DOF fused) is enabled. If you need
  linear acceleration, gravity, or raw gyro, add additional
  sh2_setSensorConfig() calls in imu_enable_rotation_vector().
